# Design System Acceptance — 验收门禁

> 项目执行时拷贝本表到 `docs/design-system/ACCEPTANCE_REPORT.md` 并填写证据；不存在的组件用 N/A，不要假装 PASS。自动化检查与人工检查必须分开记录。

## 证据格式

`ID | 状态(PASS/FAIL/BLOCKED/NOT TESTED/N/A) | 页面/组件/主题/视口 | 验证方法 | 证据链接或命令 | 责任与下一步`

## P0：阻断上线

- [ ] P0-01：没有破坏既有业务流程、订单状态、权限或关键数据路径。
- [ ] P0-02：所有主要操作均可通过键盘触达，焦点可见；无键盘陷阱。
- [ ] P0-03：重要操作（支付、提交、删除、发布等）的成功、失败、处理中有可理解反馈。
- [ ] P0-04：表单可识别 Label、错误与恢复步骤；没有仅靠颜色表达的必要信息。
- [ ] P0-05：真实文本对比度满足对应 WCAG AA（通常文本 4.5:1、大文本 3:1）；必要非文本 UI 3:1。
- [ ] P0-06：320px 宽、移动/桌面常用屏宽没有阻断任务的水平溢出或被遮挡的关键操作。
- [ ] P0-07：没有凭设计示意图虚构真实商品、统计、付款状态或其他业务事实。

## P1：必须修复的重要问题

- [ ] P1-01：Radix 色阶按 1–12 级功能约定使用，且所有例外已说明。
- [ ] P1-02：颜色采用 Primitive → Semantic → Component 的映射；新增代码无未登记随机颜色。
- [ ] P1-03：排版/间距/半径/图标一致；没有页面之间的随机漂移。
- [ ] P1-04：按钮、输入框、列表项适用的 Hover、Pressed、Selected、Focus、Disabled、Loading、Error 已覆盖。
- [ ] P1-05：浅/深主题存在且经过有效测试（若项目要求），不是机械反转。
- [ ] P1-06：弹窗焦点管理、滚动和关闭行为正常。
- [ ] P1-07：内容在 200% 文字缩放时可读，适用的 reflow 条件经过测试。
- [ ] P1-08：点击目标按 WCAG 2.2 2.5.8 验收，核对允许的例外。
- [ ] P1-09：`prefers-reduced-motion` 下非必要动效得到减少或禁用。
- [ ] P1-10：已有测试/构建/类型检查未因本次改动产生回归。

## P2：品质提升项

- [ ] P2-01：首屏主任务明显，视觉焦点没有多重竞争。
- [ ] P2-02：商品、价格、数据表、图表使用一致的数值排版。
- [ ] P2-03：空态、骨架屏、错误态、长文本、极端数据有对应设计。
- [ ] P2-04：图表颜色有分类/序列/发散语义，不只依赖色相。
- [ ] P2-05：界面文案没有空泛修饰、冗余中点分隔和过多帮助文本。
- [ ] P2-06：视觉回归截图与已批准基准比对，差异有说明。
- [ ] P2-07：没有不必要的依赖、资源体积或持续动画负担。
- [ ] P2-08：具备组件示例、Token 文档、主题说明及后续维护规范。

## 测试建议（仅在工程实际适配时执行）

- 静态代码：项目自己的 lint、typecheck、build、unit tests；记录精确命令和版本。
- 自动无障碍：axe-core / Playwright 或等效工具；须单独人工测试。
- 色彩对比：针对真实 CSS 解析结果的实际前景/背景组合测量，不可从 Token 名称推断。
- 浏览器检查：Chrome / Safari / Firefox，按目标用户与可用设备选择，不具备测试设备则标 BLOCKED。
- 视觉回归：页面/组件基准截图按 Light/Dark × 主要视口 × 关键状态矩阵保存。
- 实验报告：说明是 Mock、Staging 还是 Production，禁止将截图验收当成业务联通。
