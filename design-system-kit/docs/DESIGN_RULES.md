# Design Rules — 设计系统执行细则

> 此文件是主提示词的技术补充。它是质量约束，不是固定风格模板。项目已有已确认规范优先；偏离规则需要写明理由。

## A. Token 语义矩阵

| 分类 | 推荐语义 Token | 来源思路 | 使用原则 |
|---|---|---|---|
| 背景 | `surface.page`, `surface.subtle`, `surface.panel`, `surface.elevated` | 中性色 1–3 及主题映射 | 面板和页面层级清楚；不靠随机透明度区分 |
| 控件 | `control.default`, `.hover`, `.pressed`, `.selected` | 中性色/品牌色 3–5 | Pressed 是瞬时，Selected 是持续 |
| 边框 | `border.subtle`, `.default`, `.hover`, `focus.ring` | 色阶 6–8 | 焦点清晰，不只靠颜色区分 |
| 文本 | `text.primary`, `.secondary`, `.muted`, `.inverse` | 色阶 11/12 与已验证的反色 | Muted 不是不可读；禁用状态可更低但需显著可理解 |
| 操作 | `action.primary.bg`, `.hover`, `.fg` | 9/10 及对应前景 | 检验前景与背景的实际对比度 |
| 状态 | `status.success/warning/danger/info` 的背景/边框/文字 | Jade/Amber/Ruby/Blue 等 | 警告不能只靠颜色表达 |
| 图表 | `chart.categorical.n`, `.sequential.n`, `.diverging.n` | 独立配色 | 不与业务状态色混用造成误判 |

若需要用精确品牌色 `#...`，用品牌层或独立定制色板管理，不应任意替换单个 Radix 色阶。

## B. 色彩设计检查表

- 品牌有 1 个主色和 0–2 个辅助色（特殊项目可解释例外），不是 UI 一共只有三种色。
- 至少 1 套中性色板和成功/警告/错误状态色板。
- Light/Dark/高对比或 forced-colors 按项目支持范围测试。
- 颜色必须服务于信息、引导或品牌，不重复强调。
- 对比度按最终渲染背景测量；透明叠加、图片背景、Hover 都需单独判断。
- 设计输入支持 OKLCH/P3 的话要有 sRGB 回退与实际设备测试。
- 禁止把品牌蓝用于所有文字、背景、描边，避免“每一处都是重点”。

## C. 排版 Token 建议

| 角色 | 起始参数（非强制） | 说明 |
|---|---|---|
| display | 48–64px / 1.1–1.2 | 官网主要品牌文案；手机独立调整 |
| h1 | 32px / 1.25–1.4 | 一个页面清晰的主标题 |
| h2 | 24px / 1.3–1.45 | 区块标题 |
| h3 | 20px / 1.35–1.5 | 子区域、对话框 |
| body | 16px / 1.5–1.7 | 阅读文本 |
| body-sm | 14px / 1.45–1.6 | 工具栏、表格、辅助信息 |
| caption | 12px / 1.4–1.6 | 次要标签，不能承载必须阅读的长内容 |

- 中文和拉丁字符使用经过验证的字体回退栈；优先系统字体以减少加载成本。
- 数值用 `font-variant-numeric: tabular-nums;`；金额与统计指标有统一小数位和货币展示规则。
- 避免 `<div>` 伪造 `<button>`、`<h1>`、`<label>` 的语义，组件应保留原生可访问性。
- 小屏不能通过任意缩小字号解决布局不足；应重新排列和折行。

## D. 间距、栅格、圆角、层级

- 基础 4px 节奏；推荐序列 `0, 4, 8, 12, 16, 20, 24, 32, 40, 48, 64, 80, 96`。
- 信息密集页面可以用 8/12/16 的紧凑组合；营销落地页可以用 24/48/64 的节奏。
- 间距是 Token，屏幕断点依据内容压力与任务决定；不要盲目套固定模板。
- 圆角样式例：4/8/12/16/20/9999px；控制数量，不让所有组件有独立角度。
- 边框、分割线一般 1px。仅在测试高 DPI 与对比之后使用 0.5px 修正；焦点环不得因此退化。
- 表格密集型页面更重视对齐、间距、数字稳定；不要用大卡片代替所有表格。
- 文本截断须有完整信息获取路径（tooltip、详情页、展开）；订单号等支持复制。

## E. 组件状态合同（必须逐组件确认适用状态）

| 组件 | 必备关注点 |
|---|---|
| Button | 主/次/危险/文本/图标；Loading 不可重复提交；Focus-visible；Disabled 原因 |
| Input | Label、Placeholder 非 Label、错误提示、输入限制、粘贴与自动填充 |
| Select / Combobox | 键盘导航、选中状态、空值、搜索与列表尺寸、弹层位置 |
| Checkbox / Switch | 标签可点、状态明确、可键盘操作、禁用解释 |
| Dialog | 打开关闭、Escape、焦点移入/返回、滚动锁定、标题语义 |
| Table | 对齐、排序语义、空数据、错误和加载、移动端方案、列隐藏原则 |
| Tabs | 当前状态、键盘操作、内容归属、URL/刷新持久化（按需） |
| Toast | 不独占关键反馈、适当停留时长、可读及辅助技术通知 |
| Skeleton | 尺寸稳定、避免布局跳动、减少动画支持 |
| Empty / Error | 原因、可恢复动作、联系路径，禁止泛泛“出错了” |
| Status / Progress | 状态文字+非纯颜色提示、长任务可查询、完成与失败分离 |

## F. 可访问性和内容

- 对照 WCAG 2.2 AA，检查 1.4.3、1.4.11、1.4.10、2.1.1、2.4.7、2.4.11、2.5.8、3.3.x、4.1.2 等适用条目。
- 普通文本 4.5:1、大文本 3:1、关键 UI 3:1，是不能省略的验证门槛；并非所有文字都只满足 3:1 即可。
- 指针目标 24×24 CSS px 为 WCAG 2.2 AA 通常规则并有例外；移动产品优选 44–48px 是舒适性建议。
- 统一按钮动词、错误文本与时间/数字/货币格式，界面必须显示实际服务的交付规则。
- 不凭借单一颜色区分正负、成功失败、必填与错误；必须提供其他视觉或文字线索。
- 不使用难以关闭的剧烈动效；支持 `prefers-reduced-motion`。

## G. 动效和性能

- 动效 Token 例：`fast=120ms`、`normal=200ms`、`slow=280ms`；根据组件和用户测试调整。
- Transition 只改变有意义的状态，不在每个元素上默认加 `transition: all`。
- 图片、字体、阴影、模糊、动画需评估加载性能与低性能设备。
- 视觉数据展示有空态/慢网/错误态。不要使用虚构业务数字制造“产品成熟”的错觉。

## H. AI 风格反模式

- 全站每张卡片渐变发光 / 大面积玻璃拟态 / 随意漂浮 3D 元素。
- 功能页面动辄 50px 大标题、每项有重复解释、到处“· / |”。
- 每个页面临时新配色、新图标风格、新阴影、新半径。
- 彩色徽章替代真正的状态信息；只靠动画告诉用户发生了什么。
- 登录、付款、删除等关键流程缺少状态反馈与二次确认。
- 数字统计来源不明、商品属性含糊、交付规则被视觉装饰遮盖。
- 大量独立 Magic Number 和未标记的 CSS 例外。

## I. 设计审查输出格式

每个问题给出：`严重程度(P0阻断/P1重要/P2建议) | 页面及组件 | 可复现证据 | 违反的规则 | 最小改动 | 回归验证`。

例如：`P1 | 商品详情/主购买按钮 | #AAA 文本置于 #DDD 背景，实测对比 1.7:1 | WCAG 1.4.3 | 映射为 --text-primary + 验证背景 | 375px/1440px Light&Dark`。示例数值仅展示报告格式，不代表真实测量。
