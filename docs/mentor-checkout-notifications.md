# 导师下单与付款声明提醒

## 支付边界

当前系统是学员向导师自行转账、导师人工核对的流程，不是支付网关。
“我已付款”只提交付款声明。导师核对后才能把订单变为 `paid` 并开通服务。
邮件必须表述为“学员声明已付款，待核实”，不能把声明当成到账回执。

下单恢复使用同一请求 ID 重试：订单与声明在数据库同一事务写入，响应丢失也不能重复创建订单。
旧版留下的手工付款订单允许补交声明；仅尚未付款、没有声明的手工付款订单可以取消。
旧线上支付入口也执行相同的自购、有效权益、待处理订单及事务锁检查，
不把 Stripe 或无手工收款方式的订单转换为手工付款；原支付 webhook 不变。
导师拒绝声明后订单终结为 `failed`，保留记录，不复活旧声明。
确认服务期限与每周问题数量使用下单时快照，后续套餐编辑不影响已购权益。

## 头像

公开导师资料优先读取绑定所有者的站内头像，未绑定或头像为空才使用导师备用头像。
图片地址失效时显示同尺寸姓名首字；头像更新后重新尝试加载。

## 发信配置

业务提醒不使用 Supabase 登录验证码模板。独立通知 Worker 从私有 outbox 领取任务，
收件人由服务端根据导师所有者解析已验证的站内邮箱，客户端不能指定收件邮箱。
同一付款声明只产生一个通知事件；重试不会重复入队。
每次只领取下一条任务，远端限流期间不预领其他任务，也不消耗它们的重试预算。
邮件失败不撤销订单或声明，也不阻止站内付款待办。

在服务器 `/etc/elliott-wave/gateway.env` 安全配置以下项，不放入浏览器、Git 或聊天：

| 配置 | 含义 |
| --- | --- |
| `SUPABASE_URL` | 已有数据库项目地址 |
| `SUPABASE_SERVICE_ROLE_KEY` | 已有服务端专用密钥 |
| `MENTOR_EMAIL_SITE_URL` | 邮件内站点地址，默认 `https://wavekb.com`，独立于旧登录配置 |
| `MENTOR_EMAIL_ENABLED` | 默认 `false`；配置发信后才设为 `true` |
| `MENTOR_EMAIL_API_KEY` | Resend 发信密钥，仅服务端 |
| `MENTOR_EMAIL_FROM` | 已验证发件域下的发件地址 |
| `MENTOR_EMAIL_POLL_SECONDS` | 轮询间隔，默认 15 秒 |

未启用、缺少发信配置时 Worker 不领取任务，不会虚报发送成功。
配置完成后由运维重启 `elliott-wave-mentor-notifications.service`。
通过服务商接收只证明 `accepted`，不证明导师邮箱已收到；实际 `delivered` 必须有服务商投递事件或收件箱证据。
不要为验收把真实导师的邮箱替换为测试邮箱。

1. 等待同一提交的 Ubuntu `Verify WaveKB release` 全部门禁通过。
2. Backend-first：使用现有人工批准的后端工作流，依次执行精确迁移
   `202610080002_mentor_checkout_recovery.sql` 与 `202610080003_mentor_payment_notifications.sql`。
   未知 schema 拒绝发布；公开最终 marker 应为 `202610080003`。
   若同时发布后续 YouTube 接入批次，继续精确迁移到 `202610080004`，以
   [YouTube 配置清单](./youtube-sync-setup.md) 的最新门禁为准。
3. 发布同一 SHA 的 Gateway 和通知 Worker，保留旧代码与 unit 的回滚副本。
4. 安全配置已验证发件域与密钥，再由可控测试收件人验证一条提醒。
5. 最后发布同一 SHA 的 Next 前端并验收手机/桌面流程。

验收区分：组件/数据库测试、真实账号登录、付款声明提交、导师确认、发信服务接受、邮箱实际收到。
任何一项未完成必须明确标注，不能把测试夹具当成真实到账或把 PR 当成已上线。
生产账号验收只使用专用账号和可控导师；不得向真实导师发假付款提醒，也不操作真实资金。
