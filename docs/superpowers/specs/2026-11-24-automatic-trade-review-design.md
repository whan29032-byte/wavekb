# WaveKB 自动交易复盘设计

> **已被替代：** 本文是 Binance 单平台版本，不再作为实施依据。当前设计见 `docs/superpowers/specs/2026-11-24-multi-exchange-automatic-trade-review-design.md`。

日期：2026-11-24
状态：已确认，待实施

## 1. 意图

用自动交易数据复盘替换当前以 11 步手工分析为中心的工作台体验。用户绑定现有的币安 U 本位合约观察 API 后，系统自动同步账户权益、成交、已实现盈亏、手续费、资金费和转入转出，直接生成账户概览、交易统计和单笔复盘。

复盘不再使用分步向导。单笔交易页面只保留三个可选的主观输入：交易理由、是否遵守计划、下次改进；其余字段由交易所数据自动填写。AI 可结合用户选择的 WaveKB 书籍知识库生成带来源的复盘建议。

## 2. 当前状态与约束

- WaveKB 现有 `/workbench` 以 11 步 `workbench_analyses` 和私人记录列表为主。
- 现有币安连接只同步账户权益、钱包余额、未实现盈亏和净转入转出，每 15 分钟执行一次；没有成交明细，因而无法生成真实单笔复盘。
- 现有币安 API 密钥由网关加密保存，浏览器只能看到末四位；这一安全边界继续复用。
- 现有实时排行榜只公开用户明确同意的聚合金额和收益率。新成交、仓位和复盘数据必须始终私有。
- 币安 U 本位成交历史当前最多查询最近 3 个月，并要求使用有界时间窗口分页；初次回补因此以最近 90 天为上限。
- R 倍数需要事前风险或初始止损，交易所成交历史不能可靠推导；没有用户输入时必须显示“未设置”，不能伪造。
- 本项目独立实现 WaveKB 的交互、组件、数据模型和视觉，不复制 `lioil.lol` 的代码、品牌、文案或界面。

## 3. 目标

1. 打开交易工作台即可看到自动生成的账户复盘，不再先创建 11 步分析。
2. 新增币安成交与资金事件的安全、幂等、可续传同步。
3. 自动生成资金曲线、回撤、交易日历、胜率、盈亏比、净盈利、手续费、资金费和品种归因。
4. 点击任意已平仓交易即可进入一个页面完成复盘。
5. AI 只能在用户主动触发时读取该笔交易和用户选择的知识库，并返回带来源、可复核的建议。
6. 保留已有数据，避免删除用户过去的分析和私人记录。
7. 移动端和 iOS PWA 中可完整查看仪表盘、筛选交易并填写极简复盘。

## 4. 非目标

- 不引入返佣、订阅、充值码或对方的运营后台。
- 不做自动下单、跟单、交易信号或交易建议。
- 首版不支持币安以外的交易所，不支持现货、币本位和多资产保证金。
- 不把私人成交、订单、仓位、资金流水或复盘内容加入公开排行榜。
- 不根据盈亏结果倒推波浪结构，不把 AI 输出写成确定结论。
- 不要求用户重新录入交易所已经提供的数据。

## 5. 反目标

以下任一情况都视为失败：

- 用户仍需经过多个步骤才能看到第一份复盘。
- 同一笔成交因重复同步被重复计入盈亏。
- 手续费、资金费或转入转出被错误计入交易收益。
- 在没有初始止损或计划风险时显示虚假的 R 倍数。
- 公开页面、浏览器接口或日志泄露 API 密钥、订单、仓位或私人复盘。
- 为了替换工作台而删除现有用户数据。
- 界面变成对来源网站的换皮复制。

## 6. 已考虑的方案

### 方案 A：完全删除现有工作台并只保留交易数据

优点是页面最少；缺点是会丢失 WaveKB 的私人日记、知识库和 AI 联动价值，也会迫使已有 11 步数据迁移或删除。

### 方案 B：WaveKB 原生融合（已选）

用自动交易仪表盘替换 `/workbench` 首页和默认复盘流程，单笔交易进入极简单页复盘；私人日记、研究草稿、知识库和 AI 作为次级能力保留。既有 11 步分析不再提供新建入口，但历史记录只读保留。

### 方案 C：新增第二个独立交易工作台

风险较低，但会形成两个含义相近的工作台和两套复盘入口，增加导航和维护成本。

选择方案 B，因为它真正解决“11 步太麻烦”，同时保留 WaveKB 自身的数据和知识优势。

## 7. 用户体验

### 7.1 工作台首页 `/workbench`

未绑定币安时，显示简洁的连接说明、只读权限提示和绑定入口，不渲染假的演示业绩。

已绑定后按以下顺序展示：

1. 顶部状态：连接名称、最近同步时间、同步状态、手动刷新和管理连接。
2. 时间范围：7 天、30 天、90 天、全部可用历史；“全部”最多覆盖实际已同步的数据。
3. 核心指标：当前权益、累计盈利、时间加权收益率、已实现净盈亏、最大回撤、胜率。
4. 资金曲线：权益与累计净盈利，转入转出作为事件标记，不伪装成盈利。
5. 交易日历：每天使用已实现净盈亏着色；当天有未平仓变化时单独标识。
6. 归因区：品种、方向、持仓时长和日期/时段维度；默认只显示最有解释力的前几项。
7. 最近交易：方向、品种、开平仓时间、净盈亏、手续费、复盘状态；点击进入单笔页面。

首页不出现“新建分析”或“11 步”按钮。私人日记、研究草稿和历史分析放入较弱的次级导航。

### 7.2 单笔复盘 `/workbench/trades/[id]`

自动信息只读展示：品种、方向、平均开仓价、平均平仓价、数量、开平仓时间、持仓时长、已实现盈亏、手续费、资金费和净盈亏。

用户输入只有三项，全部可选并自动保存：

- 交易理由：自由文本和少量自定义标签。
- 是否遵守计划：未选择 / 是 / 部分 / 否。
- 下次改进：自由文本。

用户可以额外填写“计划止损价”或“计划风险金额”。只有存在有效风险基准时才计算 R 倍数，并清楚标明计算来源。

页面提供一个“AI 辅助复盘”按钮。触发前可选择全部知识库或单独选择一本书；默认沿用用户上次选择。AI 结果与用户原文分区展示，不会覆盖用户填写内容。

### 7.3 旧数据

- 已有 `private_entries` 继续可读写，日记和草稿保留。
- 已有 `workbench_analyses` 从“历史分析”入口只读访问。
- `/workbench/analysis/new` 不再出现在界面；上线稳定后再决定是否重定向到工作台首页。
- 不自动把旧分析伪装成交易所成交记录。

## 8. 数据设计

继续使用 `exchange_connections`、`exchange_connection_secrets` 和 `trading_equity_snapshots`，新增以下私有表：

### 8.1 `trading_sync_cursors`

每个连接保存成交和资金事件的同步游标、回补起点、最近成功时间、错误码和租约。服务端使用租约防止手动同步和定时任务并发重复写入。

同步使用 `sync_batch_id`/`generation` 区分准备中与已发布数据。远端 API 拉取可以分阶段进行，但成交、收入事件、游标和交易周期必须通过受控 RPC 在同一个数据库事务中发布；任一阶段失败都不得推进已发布游标。

### 8.2 `trading_fills`

保存标准化成交：连接、所有者、交易所成交 ID、订单 ID、品种、方向、仓位方向、价格、数量、已实现盈亏、手续费、手续费资产、maker/taker 和成交时间。

唯一键至少包含 `(connection_id, symbol, exchange_trade_id)`，所有写入使用 upsert，重复同步必须幂等。

### 8.3 `trading_income_events`

保存资金费和其他需要独立核算的账户事件。转入转出继续服务于时间加权收益率，不计入交易盈利；资金费计入对应交易周期或账户净盈亏；未知事件先保留类型并排除出已定义指标。

### 8.4 `trading_trade_cycles`

由成交重建的已平仓交易周期。按 `(symbol, position_side)` 维护净持仓，从零仓开始，到再次回到零仓结束；反向穿越零仓时拆成结束周期和新周期。首版同时支持单向持仓的 `BOTH` 与双向持仓的 `LONG/SHORT`。

保存聚合开平仓价格、数量、起止时间、已实现盈亏、手续费、资金费和净盈亏。该表由服务端重建，浏览器不得直接写入。

交易周期使用“连接 + 品种 + 仓位方向 + 开仓成交 ID”作为稳定业务键并采用 upsert。重建不得全表删除后重新生成，避免破坏用户复盘和 AI 任务引用。首次 90 天回补起点之前的净持仓未知；从回补起点到首次归零的片段标记为 `incomplete_opening_history`，不纳入胜率、盈亏比或单笔复盘。

### 8.5 `trading_trade_reviews`

与交易周期一对一，保存三个可选主观字段、自定义标签、计划止损/风险、可计算的 R 倍数、AI 任务引用和 AI 结果引用。用户只能访问并修改自己的记录；交易所自动字段不可由浏览器覆盖。

浏览器只获得读取权限。三个主观字段、标签和计划风险通过窄写入 RPC 修改；RPC 从登录身份与连接归属推导所有者，不能接受客户端任意覆盖服务端计算字段。

### 8.6 聚合方式

首版通过受控 RPC/服务端查询生成时间范围汇总和日维度序列，不提前增加容易失真的缓存表。数据量达到阈值后再增加可重建的日汇总表。

## 9. 同步与计算

### 9.1 同步流程

1. 复用已加密的币安凭据和现有 15 分钟定时任务。
2. 初次连接回补最近 90 天内可获取的成交，按官方限制切分时间窗口并分页。
3. 后续从最后成功游标增量同步；每个远端 ID 幂等写入。
4. 同步账户权益、转入转出、成交和资金费成功后，在同一受控流程中重建受影响的交易周期。
5. 任一阶段失败都保留上次成功数据和游标，不把半成品标记为最新。
6. 手动刷新遵守节流；页面展示明确的同步中、部分历史、错误和已更新状态。

首次回补先写入未发布批次，完成交易周期重建后一次发布。迟到或乱序成交触发受影响时间段的幂等重建。连接尚未完成回补时只展示“部分历史”，不能提前呈现为完整统计。

### 9.2 指标口径

- 已实现净盈亏 = 已实现盈亏 − 手续费 + 已归属资金费。
- 胜率 = 净盈亏大于 0 的已平仓周期数 / 已平仓周期总数。
- 盈亏比同时展示平均盈利/平均亏损与 Profit Factor，避免只给一个含糊数字。
- 最大回撤来自权益曲线高点到后续低点，不能从单笔盈亏简单相加替代。
- 时间加权收益率继续剔除外部转入转出。
- 累计盈利继续使用当前权益减初始权益和净外部资金流。
- R 倍数仅在计划风险有效时计算；否则为 null。
- MFE/MAE 作为可选的低优先级估算：使用公开 K 线在持仓区间计算，并标注粒度与“估算”；不参与排行榜和硬风控结论。
- 成交历史最多回补 90 天，但权益曲线、最大回撤和 TWR 只能从绑定后已有权益快照开始。界面分别标注“交易历史覆盖范围”和“权益跟踪开始时间”，不从成交倒推历史权益。
- 资金费仅在同品种当时存在唯一明确交易周期时归属；双向持仓同时存在或历史不完整时保留为账户级 `unallocated`，不猜测分摊。
- 非 USDT 手续费和收入同时保存原始金额与资产；缺少可靠换算价时不纳入 USDT 净盈亏，并显示“部分费用未折算”。
- 数据库存储 UTC；日历聚合接受受限 IANA 时区，默认浏览器时区，无法获取时回退 `Asia/Shanghai`。

## 10. AI 与知识库

新增 `trade_review` 类型任务，输入只包含用户拥有的已平仓周期、三个主观字段、可用的计划风险和用户选择的知识库范围。

`ai_jobs` 增加 `trade_cycle_id` 或通用 subject 引用，并约束旧分析与交易周期只能二选一。`trade_review` 使用独立的输入标准化、所有权校验、提示词、输出 schema、规则闸门和 worker 分支，不把交易数据伪装成旧 `wave_analysis`。

输出结构：

1. 事实摘要：只复述确定性成交数据。
2. 纪律观察：明确区分用户陈述和模型推断。
3. 波浪/结构假设：证据不足时必须返回未知项，不强行数浪。
4. 关联知识：返回书籍、章节/知识单元和可点击来源。
5. 下次检查清单：不包含买卖指令、收益承诺或自动执行建议。

模型输出先经过结构校验和现有规则闸门；失败不会覆盖用户复盘，也不会改变交易统计。

## 11. 隐私与安全

- 新表全部启用 RLS，拥有者只能读取自己的记录；自动同步和周期重建仅由 service role 执行。
- 含 `connection_id` 与 `owner_id` 的私有表必须通过组合外键或 `exists(exchange_connections...)` 校验真实归属，不能只信任可重复写入的 `owner_id`。
- API 密钥不迁移、不回显、不写日志，继续使用 AES-256-GCM 密文和现有密钥轮换机制。
- 新增接口沿用登录校验、来源校验、请求体上限和 `no-store`。
- 公开排行榜继续只调用独立聚合 RPC；不得 join 成交、资金事件或复盘表。
- 断开连接时立即停用密钥；是否保留历史复盘由用户明确选择，默认保留只读历史并停止同步。
- 数据导出与删除必须按用户范围执行，并写入必要的管理审计，不记录敏感正文。

## 12. 视觉和交互原则

- 使用 WaveKB 现有设计令牌、字体、间距和组件，不照搬来源站。
- 减少层层卡片和装饰性渐变；优先使用清晰的分隔、表格、曲线和数字层级，降低“AI 模板感”。
- 盈亏颜色不是唯一信息编码，同时显示正负号、文字或图标。
- 图表支持键盘焦点、文本摘要和移动端横向滚动/简化视图。
- 首屏只展示最重要的 6 个指标，详细统计按需展开。

## 13. 测试与验收

### 数据与同步

- 同一批远端成交重复同步不会新增重复记录或改变结果。
- 分页、中断恢复、90 天边界、手动/定时并发和游标回滚均有测试。
- 截断开头历史、乱序/迟到成交、同步批次失败回滚、稳定周期键重建后复盘引用不变均有精确数值夹具。
- 单向、双向、部分平仓、加仓、减仓和反手穿越零仓的周期重建结果正确。
- 手续费、非 USDT 费用、资金费归属歧义和转入转出分别按定义进入或排除指标。
- R 倍数在缺少计划风险时严格为空。
- UTC 到用户时区的跨午夜与 DST 边界有测试。

### 权限与安全

- 普通用户无法读取他人的成交、资金事件、周期和复盘。
- 浏览器无法写交易所事实字段或调用 service-role RPC。
- 排行榜响应不包含任何新增私有字段。
- 错误、日志和 AI 输入审计不出现密钥和完整原始响应。

### 页面

- 未连接、同步中、空历史、部分历史、正常和错误状态均有组件测试。
- 首页不再出现 11 步新建入口。
- 单笔页面只显示三个主观复盘字段为主要编辑项。
- 桌面、移动端和 PWA 安装模式均可完成查看、筛选、编辑和 AI 请求。

### 完成标准

- 相关单元、数据库、网关、页面和端到端测试通过。
- TypeScript 类型检查、Lint 和生产构建通过。
- 生产迁移先执行，网关兼容旧前端；部署后再切换新工作台页面。
- 现有排行榜、币安连接、私人记录和历史分析没有回归。

## 14. 实施顺序

1. 以 additive migration 增加数据库表、RLS、窄写入/批次发布 RPC 和周期重建测试。
2. 币安客户端增加成交/资金费分页与增量同步，网关保持新旧前端双版本兼容。
3. 后台执行 90 天回补并验证部分历史、截断历史和幂等重建。
4. 在 feature flag 后实现工作台汇总查询和自动复盘首页。
5. 实现极简单笔复盘、自动保存和旧数据只读入口。
6. 增加 AI `trade_review` 任务与知识库选择。
7. 完成移动端、可访问性、监控、迁移验证后切换生产工作台。

## 15. 需要实现者遵守的决定

- 默认入口必须是自动数据复盘，不是手工向导。
- 不删除旧数据，但不再推广或新建 11 步分析。
- 不复制来源项目代码；只借鉴功能类别。
- 任何无法从确定数据计算的指标都显示未知，不用近似值冒充事实。
- 首版只做币安 U 本位合约，不扩大交易所范围。
