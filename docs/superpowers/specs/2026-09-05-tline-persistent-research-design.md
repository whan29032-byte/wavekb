# WaveKB 研报持久化与后台增量同步设计

状态：用户已确认本书面设计，开始按实施计划开发；尚未上线。

## 1. 目标与范围

用户要求：第三方研报只由后台获取并存储；用户刷新、分页、搜索和阅读已同步内容时不再调用 Tline，避免延迟与重复计费。

保留当前 Next.js 架构、站内研报详情、每页 30 篇、前后翻页、关键词搜索、机构筛选与资产标签。经济日历和监控均按用户最新指示暂不实现。不重构其他 UI，不运行真实发帖验收。

已完成的分页/搜索提交为 `c1ead90163e8e91709f8a0574d1bfbee2d7a6879`。初次 Actions 33971418457 在任何生产上传/激活前取消；实施前重新核实，后续 Actions 33972332294 已成功发布该提交，生产健康接口也返回 `c1ead90`。持久化发布将以实际线上版本为备份和回滚基准，不使用过期的 `258dfcf` 状态。

## 2. 方案选择

采用服务器独立 SQLite 文件，保存第三方研究目录和同步状态。

- 相比 JSON 文件：支持事务、索引、去重更新及一致性读取，后续数据增长不必每次解析整个历史文件。
- 相比新增 Supabase 表：不涉及现有用户数据库、RLS、生产迁移凭据或用户数据备份体系。
- 不是把数据存到开发者 Mac；生产网站不依赖开发机在线。

运行时采用 Node.js 内置 `node:sqlite`，最低 Node.js 22.18，且部署预检实际运行一次内存库建表/查询探针。Node 22 的 SQLite 仍标记为实验性，因此只用该版本已经提供的基本 API，不使用 Node 26 专属功能，不自动升级生产 Node.js。若生产能力不足，停止部署并报告，不悄悄换运行时。

## 3. 存储与权限

生产路径：`/srv/wavekb-next-preview/data/tline/research.sqlite`。通过服务端环境变量 `TLINE_RESEARCH_DB_PATH` 明确传入。

该目录与 `releases/`、`.next/cache`、`public/` 完全分离，归现有部署服务账号管理，目录权限 0750，文件不向其他用户开放。路径必须是受控的绝对路径，不允许请求参数指定，不接受指向其他数据目录的符号链接。开发及测试显式使用临时目录，不能自动回退到生产路径。

- 初始化和写入只允许后台同步进程执行。
- Next.js 的读取连接以 `readOnly: true` 打开，不能创建、迁移或修复数据库。
- 这里的只读约束针对数据库结构、研报和同步状态；SQLite 原生 WAL/SHM 协调文件可能由读取连接维护，不等于修改研报或触发接口。不启用会忽略活动 WAL 的不安全 immutable 读取。
- SQLite 使用事务与 WAL；只有一个后台写入者，网页可读取已提交快照。
- SQLite、WAL、SHM、同步锁文件均不进入 Git、静态资源包或 Actions 构建产物。
- 本次不自动删除已同步历史研报；页面仍默认展示最近 7 天，旧详情保留可读。
- 数据库损坏或版本不兼容时停止写入并明确报错，禁止删除重建冒充恢复。

## 4. 数据模型

仅创建新研报库自身的以下表，不操作 Supabase：

1. `institutions`：slug 主键、机构名称、原始 JSON、更新时间。
2. `research`：研报 ID 主键、机构 slug、发布日期、上游进入数据源时间、原始 JSON、规范化搜索文本、本地更新时间。建立进入数据源时间和机构索引。
3. `sync_state`：固定单行，库结构版本、首次成功时间、最近成功时间、同步水位、最近尝试时间、最近结果状态、安全错误代码、可重试时间。

原始 JSON 保留上游提供的标题、分析、风险、论点、关键数据、资产、观点与来源链接。网页仍通过现有安全展示转换，不渲染上游 HTML，不把原始 JSON 当日志打印。

搜索文本从明确的内容字段派生，采用现有 NFKC、中英文忽略大小写、多关键词同时匹配规则；机构通过 slug 精确筛选。查询使用参数绑定，LIKE 特殊字符按字面量处理，不拼接用户 SQL。中文采用可验证的子串匹配，不在本次引入分词服务。

## 5. 后台同步

### 首次初始化

由部署流程在生产切换前显式执行一次初始化同步：先 `/institutions` 验证密钥，然后以同步开始时刻减 7 天作为固定 since，使用 `limit=200` 与 `nextCursor` 读取完整分页。

研究列表的真实响应已包含现有站内详情所需分析字段，因此保存该响应，不为每条研报额外调用详情接口。如果以后出现只提供标题的响应，只能如实展示缺失字段；不能让读者访问触发远程补抓。

首次同步完整成功（合法空集合也属于成功）才可发布本地读取版本。失败时维持旧生产代码，保留诊断和备份，不发布未初始化的空库。

### 后续增量

- 新增 `wavekb-tline-sync.service`（oneshot）与 `wavekb-tline-sync.timer`；生产每 10 分钟触发一次，与用户访问量无关。
- 进程启动时记录 `syncStartedAt`。since 使用上次成功水位减 10 分钟重叠窗口；首次使用最近 7 天起点。
- 完整读取所有游标页，按 ID 幂等更新，不重复插入。下一次水位设置为本次同步开始时刻，不能使用完成时刻以免遗漏同步期间新入库内容。
- 同步请求阶段不持有长时间 SQLite 写事务；收齐且验证响应后，用一次短事务更新机构、研报和成功水位。
- 失败不得推进成功水位或删除旧内容。记录经过脱敏的错误状态，继续提供上次成功快照。
- 保留客户端现有 429 Retry-After 退避与 401/403 不重试策略。若 Retry-After 超出当前任务可等待时间，将下次允许尝试时刻持久化；定时任务不能提前绕过限制。
- 单次仍限制 50 个分页、10,000 条记录和总执行时间；超过上限明确失败，不把部分结果当完整成功。
- systemd 防止同一 service 并发启动；初始化与手动同步也必须使用同一非阻塞跨进程锁。已有任务运行时安全跳过，不能再开第二个写入者。
- 首次初始化、手动同步和计划同步使用同一代码，不建立未经授权的公开“强制同步”接口。

### 已知数据边界

现有 API 只明确提供 since 增量语义，没有已确认的删除事件或全历史修订接口。重叠窗口可以接收重新返回的同 ID 内容，但不承诺发现窗口外的静默修订；不因某轮未返回一条历史研报而删除它。用户如需全历史回补或周期性全量校准，另行确认范围和 API 配额。

## 6. 用户读取与 UI

列表、搜索、分页、机构选项及详情只读取 SQLite。`apps/web/src/lib/tline/server.ts` 不再创建 TlineClient；密钥缺失、限流、上游断网都不应阻断已有内容的阅读。

- 每页最多 30 篇；保留已实现的搜索、筛选与前后翻页逻辑。
- 固定查询窗口包括起点与第一次打开页面时的上限，排序用进入数据源时间和 ID，避免后台新增记录把前后页推移。
- 默认仍是最近 7 天已同步研报；同步失败超过 7 天时，允许用户查看最后成功同步时的最近 7 天快照，并醒目标注数据截至时间，不能伪装实时数据或仅显示空白。
- 搜索在窗口内的全部本地研报中执行，结果计数和页面内容读取同一个事务快照。
- “刷新最近研报”改为“刷新列表”，重新打开最新的本地时间窗口并回到第一页，保留搜索/机构筛选，不启动同步。普通翻页和筛选继续固定窗口，避免后台新增造成重复。
- 展示最近成功同步时间；超过 20 分钟未成功时提示更新延迟。出现可报告的同步错误时提示继续展示已保存内容，不泄露密钥、服务器路径或上游原始错误。
- 未初始化显示“研报正在准备”与明确说明，不编造研报；生产部署必须在切换前避免这种状态。
- 本地没有的详情返回站内未找到提示，不访问上游。已保存的详情可在不再属于默认时间窗口后继续阅读。
- 保持 WaveKB 主题和移动端布局，不新增无关页面。

## 7. 打包、发布和回滚

沿用 Next.js standalone 发布和已有事务脚本，但扩展它管理同步服务与 timer 的精确先前状态。

1. 本地与 CI 完成类型检查、Lint、单元测试、生产构建和浏览器测试；构建不接收生产密钥或生产研报库。
2. 上传前只读核实 Node/SQLite 能力、Nginx 实际域名代理、服务 current 目录和当前 live SHA。不得把历史名称中的 `next-preview` 当作非生产站。
3. 在任何服务修改前备份旧代码与静态文件、原 web/service/timer 文件及 enabled/active 状态。若已有研报库，用 SQLite 一致性快照备份，不能仅复制可能存在未合并 WAL 的主文件。
4. 暂停旧同步任务，准备持久目录与候选 worker。原 `/etc/wavekb/next-preview.env` 不覆盖；新密钥继续通过 SSH stdin 写入受保护补充配置，后台 worker 使用它。Next.js 页面不依赖该密钥。
5. 对候选同步器执行初始化/增量预热，确认库结构、完整成功水位和可读取记录。首次失败不切换站点；已有库的失败不得抹掉上次成功内容。
6. 原子切换代码与 web 服务，安装/启用新的后台 service/timer。候选 worker 必须实际存在于 standalone 产物，不能引用开发源码路径或开发机。
7. 核对生产 SHA、只读页面验收、持久库状态、timer 下一次计划及 worker 退出状态，再 finalize。保留之前的代码和 SQLite 一致性备份。
8. 失败时恢复前一 web/sync/timer 配置和 enabled/active 状态；首次新增的 timer 在回滚时停用。新研报库保留，不删除任何用户或研究数据。采用向后兼容的新增结构，不做破坏性库升级。

回滚至当前 c1ead90 会恢复按请求取数实现及该版本的密钥配置引用，这是回滚版本的真实限制，必须在报告说明。若另行回滚到更早的 258dfcf，且它引用的旧密钥已被供应商撤销，不能声称旧版本研报一定可用。绝不为回滚清空 SQLite 或用户数据库。

## 8. 文件边界

- `apps/web/src/lib/tline/store.ts`：SQLite schema、只读查询、原子导入、同步状态；和 UI 无关。
- `apps/web/src/lib/tline/sync.ts`：完整游标同步、水位/重叠、错误状态、锁约束；不响应网页请求。
- `scripts/tline-sync.mjs`：后台 CLI/运维入口，受控日志与退出码。
- `apps/web/src/lib/tline/server.ts`：页面的本地只读适配；现有 client.ts 仅供同步器和显式 CLI 使用。
- `apps/web/src/lib/tline/directory.ts`、`presentation.ts`、研报列表/详情页：适配数据库计数、固定时间窗口、最后同步信息；保留现有渲染规则。
- `apps/web/scripts/prepare-standalone.mjs`：明确纳入独立 worker 和其运行依赖，不复制真实数据库。
- `scripts/deploy-release.mjs`、`.github/workflows/deploy-next-production.yml`：运行能力预检、预热、持久目录、同步单元、备份和回滚。
- 相邻 Vitest、Node 部署事务测试及研报 Playwright 验收：覆盖完整生命周期。

## 9. 验收要求

以可执行测试证明，不仅依据源码没有 fetch 字样：

- 初始多页同步、空中间页、同 ID 更新、重叠去重、完整成功才推进水位。
- 后页 429/401/403、网络失败、重复游标、进程中断、并发同步、写入失败、数据库损坏时保留既有数据与水位。
- 跨进程重开文件后记录与同步状态存在，部署路径变化不换数据文件。
- 真实本地库的搜索、机构筛选、30 条分页、恶意查询文本、Unicode 搜索、窗口边界、计数/列表一致性。
- 将读取进程的上游 fetch 设置为必定抛错且不提供 TLINE_API_KEY，列表/搜索/详情仍成功；同步器 API 调用计数不因连续刷新页面增长。
- 同步期间浏览页面得到已提交快照，不看到半页数据；新增记录不造成当前固定窗口分页重复。
- 本地无研报、未初始化、过期数据和不存在详情有真实明确状态。
- 备份后各个部署故障点均能恢复代码/服务/timer；持久库、原环境文件、上传目录和 Supabase 数据保持安全。
- 发布前生产构建、全部回归测试、桌面/手机浏览器、知识资源检查通过；跳过真实发帖。
- 生产验证新 SHA、本地查询、30 篇与搜索、同步时间、首次任务成功、计划任务存在；上线报告清楚区分“定时器已配置”和“已观察到后续一次定时执行”。

## 10. 审阅确认

本设计将用户已同意的 SQLite + 10 分钟后台同步落实为：读写分离、持久路径、独立 timer、完整事务与明确回滚。不触碰用户数据库、不删除历史研报、不把刷新变成远程同步。

用户已审阅确认；按逐任务实施计划和测试驱动流程实现，通过验收后上线。
