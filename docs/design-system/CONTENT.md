# WaveKB 文案规范

## 原则

- 先说对象和动作，再说结果；按钮使用明确动词，例如“打开知识库”“发布内容”“保存导师资料”。
- 真实业务状态必须直接显示：价格、库存、有效期、支付状态、权限、审核状态，不用装饰性文案遮盖。
- 不编造用户数量、收益、评价、成功率或“全网第一”等业务事实。
- 错误文案说明：发生了什么、用户能做什么、是否需要联系管理员。

## 术语

| 场景 | 统一用词 |
|---|---|
| 知识内容 | 知识库、条目、原书来源、失效边界 |
| 社区 | 板块、帖子、评论、回复、点赞、浏览 |
| 会员 | 权益、有效期、授予、撤销、审计 |
| 导师 | 方案、订单、收款方式、付款声明、权益 |
| 积分 | 积分、账本、签到、兑换、库存 |
| 后台 | 管理、审计、下架、停用、撤销 |

## 数值与时间

- 金额、积分、浏览、点赞、排名使用 `tabular-nums`。
- 中文日期使用 `zh-CN` 本地化；时间保留到分钟，必要时显示时区。
- 价格必须带币种；折扣、有效期、库存必须同时显示单位。
- 未知或空值显示“未设置”“尚未测量”，不显示 0 冒充真实数据。

## 按钮与状态

- 主按钮：打开、进入、发布、保存、兑换、确认。
- 次按钮：取消、返回、查看详情、下架、停用。
- 危险按钮：删除、撤销、退款、移除；配合二次确认。
- 加载：正在发布、正在保存、正在兑换、正在上传；不要只显示旋转图标。
- 空态：说明为什么为空，并提供下一步动作；不要只写“暂无数据”。

## 可读性

- 中文正文使用全角标点；中英文之间保留自然空格。
- 不用连续中点或竖线替代信息架构；分类、状态优先使用 Badge 或分行。
- 标题短而具体；说明文字控制在 1–2 句，避免重复解释同一件事。
